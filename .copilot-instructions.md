# Copilot Instructions for Flexible Log Analyzer

## Project Overview

You are working on **Flexible Log Analyzer**, a VS Code extension that analyzes log files using configurable YAML-based pattern matching rules. This extension provides intelligent log analysis with customizable patterns, multi-level severity detection, and enhanced visualization through tree views and minimap integration.

## Architecture & Core Components

### 🏗️ **Project Structure**
```
src/
├── extension.ts              # Main extension entry point & activation
├── config/
│   ├── configManager.ts      # YAML configuration loading & management
│   └── configValidator.ts    # Configuration validation & schemas
├── analysis/
│   └── patternMatcher.ts     # Core regex pattern matching engine
├── ui/
│   └── enhancedTreeView.ts   # Tree view with LRU caching & active file focus
├── types/
```

## Core Functionality

### 📋 **Configuration System (.logconfig files)**
- **YAML-based**: User-friendly configuration format
- **Hierarchical loading**: Workspace → User → Built-in configs
- **Hot-reload**: Automatic reanalysis when configs change
- **Detection**: Auto-detect log formats with confidence scoring
- **Language mode switching**: Automatically change VS Code language mode

```yaml
# Example .logconfig structure
version: "1.0"
name: "Web Server Logs"
detector:
  type: "first-line"
  pattern: "\\d{4}-\\d{2}-\\d{2}\\s\\d{2}:\\d{2}:\\d{2}"
  changeLanguageMode: true
matchers:
  - name: "HTTP Errors"
    pattern: "\\s(4\\d\\d|5\\d\\d)\\s"
    severity: "high"
    color: "#FF0000"
    minimap: true
```

### 🎯 **Pattern Matching Engine**
- **Regex-based**: Powerful pattern matching with customizable flags
- **Multi-severity**: Support for low/medium/high/critical levels
- **Performance optimized**: Compiled regex caching and timeout handling
- **Context extraction**: Capture surrounding lines for better analysis

### 🌳 **Enhanced Tree View**
- **Active file focus**: Shows results only for currently open file
- **LRU caching**: Intelligent caching of analysis results (configurable size)
- **Fast switching**: Instant results when switching between cached files
- **Memory management**: Automatic cleanup of oldest cached results

### ⚡ **Auto-Analysis Features**
- **File events**: Automatic analysis on open/save
- **Real-time analysis**: Optional content change analysis with debouncing
- **Deduplication**: Prevents concurrent analysis of same file
- **Configuration watching**: Auto-reanalyze when .logconfig changes

## Development Guidelines

### 🎯 **Code Style & Patterns**

1. **Type Safety First**
   - Use strict TypeScript with proper interfaces
   - Leverage types from `configTypes.ts` and `analysisTypes.ts`
   - Avoid `any` types - use proper generics instead

2. **Error Handling**
   - Use try-catch blocks with proper error logging to outputChannel
   - Provide user-friendly error messages via `vscode.window.showErrorMessage`
   - Clean up resources in finally blocks

3. **Performance Considerations**
   - Use debouncing for file change events (configurable delay)
   - Implement proper caching strategies (LRU for tree view)
   - Add timeout handling for large file analysis
   - Use `analysisInProgress` Map to prevent duplicate analysis

4. **VS Code Integration**
   - Use `outputChannel` for all debug/info logging
   - Implement proper disposal patterns for subscriptions
   - Follow VS Code UX guidelines for progress indication
   - Use appropriate icons and contexts for commands

## Performance & Memory Management

### 🚀 **Optimization Strategies**
1. **Lazy Loading**: Load configurations only when needed
2. **Regex Compilation**: Cache compiled regex patterns
3. **Debouncing**: Prevent excessive analysis on rapid file changes
4. **Memory Limits**: Respect `maxResultsPerFile` and cache size limits
5. **Timeout Handling**: Prevent infinite analysis on complex patterns

### 📊 **Monitoring & Debugging**
- Use `outputChannel.appendLine()` for all debug information
- Include timestamps and call IDs for tracking analysis calls
- Log performance metrics (analysis time, file size, match count)
- Track cache hit/miss ratios for optimization
